# התראות מייל

השרת שולח מיילים דרך Resend API. אין לשמור מפתחות API בקוד או להעלות אותם למאגר.

## הגדרת Resend

1. פתחי חשבון ב־Resend ועברי אל `API Keys`. צרי מפתח עם הרשאת שליחת מיילים והעתיקי אותו; שמרי אותו פרטי.
2. לשליחת בדיקה ראשונית, הגדירי `MAIL_FROM="Home Management <onboarding@resend.dev>"`. כתובת זו מאפשרת בדרך כלל שליחה רק לכתובת חשבון Resend שלך.
3. כדי לשלוח למשתמשים אחרים, הוסיפי דומיין משלך ב־`Domains` ב־Resend. הוסיפי אצל ספק ה־DNS את הרשומות ש־Resend מציגי, והמתיני עד שהדומיין יאומת. לאחר מכן הגדירי `MAIL_FROM` לכתובת מהדומיין המאומת.
4. העתיקי את `.env.example` אל `.env` המקומי ועדכני בו את `DATABASE_URI`, `ACCESS_TOKEN_SECRET`, `RESEND_API_KEY`, `MAIL_FROM` ו־`APP_URL`. אין צורך להגדיר פרטי AWS.
5. הגדירי את `APP_URL` לכתובת אפליקציית React; התראות משימות יקשרו אל `/todos`.
6. הפעילי מחדש את שרת Node לאחר שינוי ההגדרות.
7. משתמשים צריכים להזין כתובת מייל ולאשר קבלת הודעות בהרשמה. רק משתמשים שאישרו יקבלו מיילי משימות, ורק מנהלים שאישרו יקבלו התראות ניהול.

## אישור חד־פעמי למשתמש קיים

לאחר הגדרת Resend, הריצי את הפקודה מתיקיית `node` והחליפי את הערך בשם המשתמש המדויק:

```powershell
node scripts/sendEmailConfirmation.js <username>
```

הפקודה שולחת רק למשתמש רגיל שיש לו כתובת מייל שמורה והסכמה לקבלת הודעות. לאחר שליחה מוצלחת, זמן השליחה נשמר כדי למנוע שליחה חוזרת. משתמשים חדשים שיאשרו קבלת הודעות יקבלו את האישור אוטומטית בהרשמה.

## אירועי מייל

- כשנפתחת רשימת משימות מתוזמנת או כשנוספת/נפתחת מחדש המשימה הראשונה: נשלח למשתמשים ולמנהלים שאישרו מייל עם המשימות וקישור אל `/todos`.
- כשהמשימה הגלויה האחרונה הושלמה: נשלח מייל למנהלים שאישרו.
- בשעה 12:00 או אחריה, ביום תחילת ההשכרה, אם נותרו משימות פתוחות: נשלחת למנהלים שאישרו תזכורת פעם אחת באותו יום.
- כשכמות של מוצר יורדת מכמות חיובית לאפס: נשלחת למנהלים שאישרו התראת מלאי. אפס הוא ערך המינימום הנוכחי בסכמה.
- כשנרשמת הכנסה חדשה או תשלום חדש עבור השכרה: נשלחת למנהלים שאישרו התראה.

אם חסרים `RESEND_API_KEY` או `MAIL_FROM`, השליחה תידלג והדבר יירשם ביומן; פעולות המערכת עדיין יושלמו. שגיאות Resend נרשמות ביומן השרת.
